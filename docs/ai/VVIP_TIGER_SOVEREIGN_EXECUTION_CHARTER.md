# VVIP TIGER Sovereign Execution Charter

## Status
**OFFICIALLY ADOPTED — 2026-08-07**

This charter records the owner-approved engineering execution model for VVIP TIGER. It governs the AI/Sovereign program and extends the existing Constitution, Proof System, Master Dossier, and 45-gate readiness model.

## Supreme execution rule
`NO EVIDENCE -> NO VERIFIED CLAIM -> NO RELEASE AUTHORITY`

## Authorized engineering autonomy
Engineering may introduce stronger architecture, security, verification, reliability, observability, testing, documentation, and operational controls directly when the change:
- preserves or strengthens fail-closed behavior;
- is reversible or reviewable through a feature branch / Draft PR;
- does not fabricate evidence or readiness;
- does not broaden owner-independent authority;
- does not perform a protected production action.

The engineering program does not need a separate owner approval for each such safe design improvement.

## Protected owner authorities
The following remain distinct owner-controlled gates and are never inferred from a general instruction to implement or improve the platform:
1. Merge Approval.
2. Database Promotion Approval.
3. Production Activation Approval.

The AI must also never autonomously transfer funds, delete production data, change owner permissions, or grant itself greater authority.

## Truth states
Only these truth states may be used by proof-backed documentation and release evidence:
- `VERIFIED`
- `DESIGNED`
- `PENDING`
- `STALE`
- `BLOCKED`

A design, simulation, target, fixture, deferred manual test, or stale artifact cannot be relabeled as verified production evidence.

## 100% definition
VVIP TIGER may report 100% production readiness only when the canonical Truth/Readiness Engine proves all required gates for the exact Release DNA with no failed, blocked, pending, deferred, simulated, assumed, stale, or missing production evidence and after all protected owner approvals required for that release have been recorded.

## Documentation rule
The Master System Dossier is part of the evidence system. It must distinguish implemented repository facts, designed contracts, measured results, manual acceptance, staging evidence, and production evidence. Documentation cannot create authority and cannot upgrade a claim to `VERIFIED` by wording alone.

## Current safety boundary
This charter is a repository governance artifact. It is not a Merge Approval, Database Promotion Approval, or Production Activation Approval. It authorizes continued safe implementation on reviewable branches while preserving those protected gates.
