# VVIP TIGER V13.1 Executable Authority Design

## 1. الصفة والسلطة

هذه الوثيقة تحول حزمة **VVIP TIGER NEXUS GENOME V13.1** وقرار المالك النهائي المعدِّل بتاريخ 2026-08-05 إلى تصميم مستودع قابل للقراءة الآلية والاختبار.

ترتيب السلطة داخل نطاق V13.1:

1. قرار المالك النهائي المسجل بتاريخ 2026-08-05.
2. `project-control/v13.1/contracts/owner_constitution.json`.
3. عقود V13.1 المجمدة واختبارات اتساقها.
4. حزمة الدولة المعتمدة وأدلتها.
5. مخططات البيانات وOpenAPI وRLS والحالات والاختبارات.
6. الكود والواجهات.
7. ملفات Word والوثائق التاريخية والتوضيحية.

يسود V13.1 وقرار المالك النهائي على أي حكم قديم متعارض. لا تحذف الوثائق التاريخية بغرض إخفاء الماضي؛ تصنف الأحكام المخالفة صراحة بأنها متجاوزة ولا تبقى فعالة بصمت.

## 2. القرارات الدستورية النهائية

### 2.1 وسائط الإعلان

- الحد العالمي النهائي هو **7 صور لكل إعلان**.
- لا يجوز رفع الحد بسبب قيمة الدفع أو الباقة أو نوع الحساب.
- الفيديو غير مفعّل في الإصدار الحالي.
- أي حكم سابق يحدد 10 صور أو يسمح بزيادة مدفوعة مصنف `SUPERSEDED_BY_V13_1_OWNER_FINAL`.

### 2.2 الظهور والتسعير

- لا يوجد رقم ظهور عالمي ثابت.
- القيمتان 250 و400 ليستا قيمتين عالميتين ولا افتراضين داخل النواة.
- كمية الظهور وسعرها يحددان فقط داخل **ختم دولة** معتمد.
- ختم الدولة يتطلب القانون والضريبة والدفع والقدرة التشغيلية واختبار اقتصاد الوحدة واعتماد المالك.
- لا بيع لخدمة ظهور لا تستطيع المنصة حجز قدرتها أو إثبات تسليمها.

### 2.3 الدردشة والتوصيل والوساطة

- الدردشة الداخلية مسموحة دستوريًا.
- التوصيل مسموح دستوريًا.
- الوساطة مسموحة دستوريًا.
- السماح الدستوري لا يساوي التفعيل الإنتاجي.
- تبقى كل وظيفة محجوبة حتى وجود عقد مستقل للحالات والصلاحيات والخصوصية والاعتدال والمسؤوليات والفشل والتدقيق والاختبارات والأدلة.

### 2.4 واتساب الخارجي

- التكامل مجهز بوصفه تكاملًا خارجيًا فقط.
- الحالة النهائية الحالية: `DISABLED`.
- لا يعد وسيلة نقل للرسائل الداخلية.
- لا يظهر أو يستدعى قبل قرار تفعيل منفصل، ومراجعة خصوصية وأمن ونسخة موافقة مستخدم وأدلة.

## 3. الثوابت الأخرى من V13.1

- الحساب عالمي، والسوق النشط ودولة الإعلان والفوترة والكيان القانوني وسياسة معالجة البيانات سياقات مستقلة.
- الذكاء الاصطناعي يقترح ويفسر ويكشف؛ لا يمنح صلاحية ولا يحرك مالًا ولا يفتح دولة ولا يصدر اعتمادًا قانونيًا نهائيًا.
- الصلاحيات مرفوضة افتراضيًا، والحسم في الخادم وRLS لا في الواجهة.
- كل حركة مالية لاحقة تحتاج دفتر قيد مزدوج، وتصحيح القيد يكون بعكس محاسبي لا بالتعديل أو الحذف.
- لا تعديل مباشر على `main`.
- لا إطلاق بلا PR وCI واختبارات وأدلة وخطة رجوع.
- لا أسرار أو قيم قانونية أو ضريبية أو مصرفية مخترعة داخل المستودع.
- لا وصف للمشروع أو الدولة أو الوظيفة بأنها جاهزة للإنتاج قبل بواباتها الفعلية.

## 4. الهدف التنفيذي

إنشاء طبقة **Executable Authority** تحقق ما يلي قبل توسيع Runtime:

- تسجيل الدستور النهائي في عقد حتمي واحد.
- اختبار القيم والحدود والقدرات المحجوبة.
- اكتشاف أي رجوع إلى 10 صور أو رقم ظهور عالمي أو منع مطلق للوظائف المسموحة.
- منع تفعيل الدردشة أو التوصيل أو الوساطة لمجرد أنها مسموحة دستوريًا.
- إبقاء واتساب الخارجي معطلًا حتى قرار مستقل.
- تصنيف التعارضات القديمة بدل تركها فعالة بصمت.
- توفير مصدر حقيقة تستهلكه الخطط اللاحقة دون نسخ القواعد يدويًا.

## 5. النهج المعماري

### 5.1 هجرة إضافية محكومة

تضاف حزمة V13.1 تحت `project-control/v13.1/`. لا يعاد بناء التطبيق دفعة واحدة، ولا تنفذ Migration إنتاجية في شريحة تثبيت الدستور.

### 5.2 فصل القرار عن التفعيل

لكل قدرة مستويان مستقلان:

- `constitutionally_allowed`: حكم المالك على جواز وجود الوظيفة.
- `activation_state`: جاهزية التنفيذ الفعلية.

هذا الفصل يمنع خطأين متعاكسين: منع وظيفة أجازها المالك، أو فتح وظيفة ناقصة لأن المالك أجاز مبدأها.

### 5.3 المصدر التنفيذي

الملف الأعلى:

`project-control/v13.1/contracts/owner_constitution.json`

لا يقرأ Runtime ملفات Word مباشرة. ملفات Word محفوظة كمرجع القرار، بينما العقود والاختبارات هي واجهة البرمجة الملزمة.

## 6. مكونات الحزمة

### 6.1 دستور المالك

يتضمن:

- هوية الإصدار والسلطة والأسبقية.
- حالة الإنتاج المحجوبة.
- سياسة الصور والفيديو.
- سياسة الظهور وختم الدولة.
- حالات الدردشة والتوصيل والوساطة.
- حالة واتساب الخارجي.
- قائمة الأحكام القديمة المتجاوزة.
- قواعد PR والاختبار والدليل والرجوع.

### 6.2 سجل القرارات

يحول القرارات الواسعة إلى معرفات ثابتة ترتبط بالعقود والاختبارات والأدلة وخطة الرجوع.

### 6.3 سجل التعارضات

يسجل على الأقل:

- `GLOBAL_IMAGE_LIMIT_10`.
- `GLOBAL_FIXED_IMPRESSIONS_250`.
- `GLOBAL_FIXED_IMPRESSIONS_400`.
- `CHAT_FORBIDDEN`.
- `DELIVERY_FORBIDDEN`.
- `MEDIATION_FORBIDDEN`.
- أي Roadmap أو وثيقة أو اختبار قديم يعيد أحد هذه الأحكام.

### 6.4 كتالوج الحالات والانتقالات

تبدأ الحزمة بحالات السلطة والعقود والأدلة والإطلاق، ثم تضيف الخطط اللاحقة حالات الإعلان والدردشة والتوصيل والوساطة والدفتر والدولة.

### 6.5 المدقق

`project-control/scripts/validate_v13_1_authority.mjs`

مسؤولياته:

- قراءة الدستور والعقود.
- فحص البنية والمراجع والتكرار.
- منع التعارض الصامت.
- منع الادعاء الإنتاجي بلا أختام.
- منع أي رقم ظهور عالمي.
- تثبيت سبع صور وعدم ارتباطها بالسعر.
- منع تفعيل قدرة محجوبة.
- إنتاج JSON حتمي للنجاح أو الفشل.

### 6.6 بوابة CI

تضاف بوابة مستقلة باسم:

`GATE_v13_1_authority_integrity`

وهي بوابة إضافية لا تستبدل بوابات الأمن أو Project Control أو الاختبارات الحالية.

## 7. تدفق التنفيذ

1. يسجل قرار المالك في الدستور التنفيذي.
2. يكتب اختبار يفشل قبل إنشاء أو تعديل العقد.
3. ينشأ الحد الأدنى من العقد لتحقيق الاختبار.
4. يربط القرار بسجل التعارضات.
5. يفحص المدقق الحزمة كاملة.
6. تشغل GitHub Actions على نتيجة الدمج المقترحة مع `main`.
7. لا ينتقل أي Runtime إلى التفعيل إلا في خطة مستقلة وبوابات مستقلة.

## 8. معالجة الأخطاء

- جميع الفحوص Fail-Closed.
- لا يصلح المدقق الملفات تلقائيًا.
- الملف المفقود أو غير القابل للقراءة فشل صريح.
- السماح الدستوري لا يزيل بوابات الأمان.
- المدخل الرسمي المفقود يبقى `PENDING` ولا يحول إلى قيمة افتراضية مخترعة.
- تغيير القرار يتطلب اختبارًا يثبت الفشل قبل التنفيذ الجديد.

رموز الفشل الأساسية المقترحة:

- `V13_CONSTITUTION_MISSING`
- `V13_CONSTITUTION_INVALID`
- `V13_IMAGE_LIMIT_NOT_SEVEN`
- `V13_IMAGE_LIMIT_PRICE_DEPENDENT`
- `V13_GLOBAL_FIXED_IMPRESSIONS_FORBIDDEN`
- `V13_CAPABILITY_ACTIVATED_WITHOUT_CONTRACT`
- `V13_WHATSAPP_MUST_REMAIN_DISABLED`
- `V13_SILENT_LEGACY_CONFLICT`
- `V13_PRODUCTION_CLAIM_WITHOUT_SEALS`

## 9. استراتيجية الاختبار

### 9.1 الاختبار الإيجابي

يثبت أن:

- V13.1 هو الدستور النهائي.
- حد الصور 7.
- الفيديو غير مفعّل.
- حد الصور لا يعتمد على السعر.
- الظهور العالمي `null`.
- الكمية والسعر يخضعان لختم الدولة.
- الدردشة والتوصيل والوساطة مسموحة دستوريًا ومحجوبة تشغيليًا.
- واتساب خارجي فقط ومعطل.
- كل تعارض قديم مصنف صراحة.

### 9.2 الاختبارات السلبية

تفشل الحزمة عند:

- إعادة 10 صور.
- إضافة زيادة صور مدفوعة.
- وضع 250 أو 400 أو أي عدد عالمي ثابت.
- تفعيل دردشة أو توصيل أو وساطة دون عقودها.
- تفعيل واتساب دون قرار مستقل.
- حذف سجل تعارض مطلوب.
- تغيير حالة الإنتاج إلى Allowed دون أختام.

### 9.3 اختبار التكامل

تشغل البوابة داخل Quality Gate المعزولة، وتثبت نظافة مساحة العمل وعدم تغير Runtime أو قاعدة البيانات في شريحة الدستور.

## 10. برنامج التنفيذ الكامل لملفات Word

بعد تثبيت الدستور، يقسم التنفيذ إلى شرائح مستقلة قابلة للاختبار:

1. سلطة V13.1 وسجل التعارضات.
2. الحساب العالمي وسياقات الدول.
3. الصلاحيات وRLS وأظرف التفويض.
4. الإعلان وسبع صور وحالات النشر.
5. الظهور وختم الدولة وحجز القدرة.
6. المحفظة والدفتر المالي المزدوج.
7. البحث والفلاتر والجينوم القطاعي للقطاعات السبعة.
8. الدردشة الداخلية.
9. التوصيل.
10. الوساطة.
11. واتساب الخارجي بوصفه قدرة معطلة حتى قرار لاحق.
12. التصميم والشاشات وإمكانية الوصول.
13. الأمن وأوضاع النجاة وSLO والتعافي.
14. حزمة الأردن وPilot محكوم.

كل شريحة لها Spec وPlan واختبارات وPR وأدلة مستقلة. هذا هو التنفيذ الكامل، وليس اختصارًا للمحتوى.

## 11. غير مشمول في شريحة الدستور

- تشغيل دفع حقيقي.
- فتح الأردن أو أي دولة.
- نشر Migration إنتاجية.
- تفعيل الدردشة أو التوصيل أو الوساطة.
- تفعيل واتساب.
- تغيير Clerk أو Supabase Runtime.
- إعادة تصميم الواجهة.

## 12. معايير قبول شريحة الدستور

- وجود عقد الدستور التنفيذي.
- نجاح اختبارات القرار النهائي.
- وجود دليل RED سابق يثبت أن الاختبار اكتشف غياب العقد.
- نجاح Quality Gate بعد إضافة العقد.
- عدم وجود فقرة متعارضة في Spec أو Plan الفعالة.
- عدم تغير Runtime أو Migrations.
- بقاء الإنتاج والدول والقدرات الحساسة محجوبة.
- PR مستقل قابل للرجوع دون أثر بيانات.
