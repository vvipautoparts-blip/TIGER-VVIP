# VVIP TIGER V13.1 Executable Authority Design

## 1. صفة هذه الوثيقة

هذه الوثيقة تحول حزمة **VVIP TIGER NEXUS GENOME V13.1** المعتمدة من مرجع Word معماري إلى تصميم مستودع قابل للتنفيذ والاختبار. لا تمنح هذه الوثيقة تصريح إنتاج، ولا تستبدل الأدلة القانونية أو الضريبية أو المالية الرسمية.

ترتيب السلطة داخل نطاق V13.1:

1. قرار المالك النهائي المسجل.
2. سجل سلطة V13.1 القابل للقراءة آليًا.
3. عقود V13.1 المجمدة واختبارات اتساقها.
4. حزمة الدولة المعتمدة وأدلتها.
5. مخططات البيانات وOpenAPI وRLS والاختبارات.
6. الكود.
7. ملفات Word والوثائق التوضيحية.

تظل V12 مرجعًا مفاهيميًا وتاريخيًا. يسود V13.1 عند التعارض ضمن نطاقه، مع حفظ التاريخ وعدم حذف الوثائق السابقة أو تزوير حالتها القديمة.

## 2. الهدف

إنشاء طبقة **Executable Authority** إضافية داخل المستودع تحقق ما يلي قبل تعديل سلوك المنتج:

- تسجيل القرارات المحمية بمعرفات ثابتة وإصدارات ومالكين ونطاقات.
- اكتشاف التعارض بين V13.1 والمرجع القديم والـRoadmap والكود.
- منع دمج قرار بلا عقد أو اختبار أو أثر واضح.
- فصل الحالة التاريخية عن الحالة التنفيذية الجديدة.
- منع الادعاء بأن الأردن أو أي دولة أو قطاع أو وظيفة إنتاجية أصبحت معتمدة قبل الأدلة والأختام.
- تحويل المخرجات اللاحقة إلى ملفات قابلة للتحقق: Schema وAPI وRLS وState Machine وLedger وSearch وEvidence.

## 3. القيود غير القابلة للاجتهاد

- المنصة دليل إعلاني بصري متعدد الدول والقطاعات.
- تنتهي رحلة المستفيد عند إظهار رقم الهاتف أو بدء الاتصال.
- لا بيع أو شراء أو توصيل أو ضمان أو حجز أموال أو وساطة أو دردشة داخل المنتج المفعّل.
- مصدر الدخل المفعّل: الإعلانات وخدمة الظهور الإعلاني الموثق فقط.
- الفيديو غير مسموح في الإصدار الحالي.
- مساحة الإعلان وشكله الأساسي وعدد الصور لا تتغير حسب قيمة الدفع.
- الحد الأعلى العالمي للصور في V13.1 هو 10، ويجوز خفضه محليًا أو قطاعيًا لأسباب موثقة، ولا يزاد مقابل المال.
- لا يوجد رقم ظهور عالمي ثابت؛ 400 قيمة Pilot محتملة داخل ختم دولة وليست قرار إنتاج عالمي.
- الحساب عالمي، والسوق النشط ودولة الإعلان والفوترة والكيان القانوني وسياسة البيانات سياقات مستقلة.
- الذكاء الاصطناعي يقترح ويفسر ويكشف فقط؛ لا يفتح دولة ولا يمنح صلاحية ولا يحرك مالًا ولا يصدر رفضًا نهائيًا.
- كل صلاحية مرفوضة افتراضيًا حتى تمنح صراحة، وتنفذ في الخادم وRLS لا في الواجهة.
- لا حركة مالية بلا قيد مزدوج، ولا تعديل أو حذف لقيد منشور؛ التصحيح بقيد عكسي جديد.
- لا تعديل مباشر على `main`، ولا إطلاق دون PR وCI واختبارات وأدلة وخطة رجوع.
- لا أسرار أو قيم قانونية أو ضريبية أو مصرفية مخترعة في GitHub أو Word أو Logs.
- لا وصف للمشروع بأنه مكتمل أو جاهز للإنتاج قبل اكتمال بوابة 12/12 والأختام الفعلية.

## 4. الحالة الحالية والتعارضات الواجب احتواؤها

المستودع الحالي يحتوي على مرجع مالك وRoadmap وتطبيق ثابت متعدد الصفحات، كما يحتوي على عناصر تاريخية قد تتعارض مع V13.1، منها:

- وصف Feed وتجربة اجتماعية في المرجع القديم.
- مرحلة اتصال خاص واحد لواحد.
- مرحلة اشتراكات واستحقاقات.
- مراجع لميزات أو مصادر دخل متعددة.
- حالة آلية قديمة تشير إلى P08 بوصفها المرحلة التالية رغم وجود أعمال وPRs أحدث.

لا تُحذف هذه العناصر مباشرة. ينشأ **Conflict Overlay** يحدد لكل عنصر:

- `ACTIVE_UNDER_V13_1`
- `SUPERSEDED_BY_V13_1`
- `HISTORICAL_ONLY`
- `PENDING_OWNER_MAPPING`
- `BLOCKED_PENDING_OFFICIAL_INPUT`

أي عنصر متعارض لا يجوز أن يبقى فعالًا بصمت.

## 5. النهج المعتمد

### 5.1 نهج إضافي لا هدمي

تضاف حزمة V13.1 تحت `project-control/v13.1/` مع وثائق مقروءة تحت `docs/architecture/v13.1/`. لا يعاد بناء التطبيق أو ترحيل قاعدة البيانات في هذه المرحلة.

### 5.2 عقود YAML بصيغة JSON-compatible YAML

تكتب ملفات `.yaml` بصيغة JSON صحيحة، وهي YAML 1.2 صحيحة أيضًا. يتيح ذلك التحقق باستخدام مكتبات Node القياسية دون إضافة Dependency جديدة، احترامًا لقيد المستودع بعدم إدخال Build Step أو Framework أو حزمة غير لازمة.

### 5.3 فصل الحقيقة عن العرض

- ملفات `project-control/v13.1/contracts/` هي المصدر التنفيذي.
- ملفات `docs/architecture/v13.1/` شرح مشتق لا يتغلب على العقود.
- ملفات Word تبقى مراجع معمارية ومصدرًا للقرار، لكن التنفيذ لا يقرأ Word مباشرة.

## 6. المكونات

### 6.1 Authority Manifest

الملف: `project-control/v13.1/authority-manifest.json`

يحتوي على:

- الإصدار `13.1.0`.
- صفة V12 وV13.1.
- حالة الإنتاج `BLOCKED`.
- قائمة العقود وأثر SHA-256 لكل ملف.
- قائمة المدخلات الرسمية المعلقة.
- قائمة المصادر التاريخية المحفوظة.
- Commit مرجعي عند التجميد.

### 6.2 Decision Registry

الملف: `project-control/v13.1/contracts/decision_registry.yaml`

كل قرار يتضمن:

- `decision_id`
- `version`
- `title_ar`
- `domain`
- `scope`
- `status`
- `owner_role`
- `rule`
- `forbidden_outcomes`
- `affected_contracts`
- `test_references`
- `evidence_requirements`
- `rollback_strategy`

### 6.3 Conflict Registry

الملف: `project-control/v13.1/contracts/conflict_registry.yaml`

يربط النص أو المرحلة أو الملف القديم بالقرار الأعلى ويمنع التعارض الصامت. لا يعدل التاريخ؛ يسجل أثر التعارض وحكمه وسبب الحكم.

### 6.4 Core State Contracts

الملفات:

- `state_catalog.yaml`
- `transition_matrix.yaml`
- `error_catalog.yaml`
- `authority_order.yaml`

تبدأ بحالات السلطة والإطلاق والدولة والعقود، وليس بكل حالات المنتج دفعة واحدة. حالات المنتج والمال والإعلان تضاف في خطط فرعية مستقلة بعد تثبيت هذه الطبقة.

### 6.5 Schemas

تضاف JSON Schemas لكل عقد لضمان:

- عدم وجود معرفات مكررة.
- منع الحالات غير المعروفة.
- منع انتقال بلا حالة مصدر وهدف.
- منع قرار فعال بلا مالك أو اختبار أو دليل مطلوب.
- منع استخدام `PRODUCTION_ALLOWED` دون أختام مكتملة.

### 6.6 Validator

الملف: `project-control/scripts/validate_v13_1_authority.mjs`

مسؤولياته:

- قراءة العقود بصفتها JSON-compatible YAML.
- التحقق من Schema.
- التحقق الدلالي بين الملفات.
- فحص التعارضات الصامتة.
- فحص الروابط اليتيمة.
- التحقق من بصمات Manifest.
- إخراج تقرير JSON وملخص Console حتمي.

رموز الفشل الأساسية:

- `V13_AUTHORITY_SCHEMA_INVALID`
- `V13_DUPLICATE_DECISION_ID`
- `V13_ORPHAN_DECISION`
- `V13_UNKNOWN_STATE`
- `V13_UNKNOWN_TRANSITION`
- `V13_SILENT_CONFLICT`
- `V13_MANIFEST_HASH_MISMATCH`
- `V13_PRODUCTION_CLAIM_WITHOUT_SEALS`

### 6.7 CI Gate

تضاف بوابة مستقلة إلى `scripts/quality-gate.sh` بعد نجاح الاختبارات الموجهة. لا تغير البوابات الحالية ولا تقللها.

اسم البوابة:

`GATE_v13_1_authority_integrity`

## 7. تدفق البيانات

1. قرار المالك أو V13.1 يولد سجل قرار.
2. القرار يرتبط بعقد أو أكثر واختبار أو أكثر.
3. Conflict Registry يصنف المراجع السابقة.
4. Validator يقرأ جميع العقود وSchemas وManifest.
5. عند أي تعارض أو رابط يتيم يفشل CI قبل الدمج.
6. عند النجاح ينتج تقرير دليل، لكنه لا يغير حالة الإنتاج إلى Allowed.
7. أي خطة لاحقة تستهلك هذه العقود ولا تنسخ القاعدة يدويًا.

## 8. معالجة الأخطاء

- جميع الأخطاء Fail-Closed.
- لا يصلح Validator الملفات تلقائيًا.
- لا يتجاهل ملفًا غير قابل للقراءة.
- لا يعتبر Word أو Comment بديلًا لعقد ناقص.
- لا يحول حالة `PENDING_OFFICIAL_INPUT` إلى Passed.
- لا يسمح بتغيير بصمة مصدر بلا تحديث قرار وManifest.
- لا يسمح لمخرجات AI بكتابة قرار فعال مباشرة.

## 9. استراتيجية الاختبار

### 9.1 اختبارات بنيوية

- ملفات مطلوبة موجودة.
- كل ملف يطابق Schema.
- جميع المعرفات فريدة.
- جميع المراجع قابلة للحل.

### 9.2 اختبارات دلالية

- V12 مصنفة `CONCEPT_REFERENCE`.
- V13.1 مصنفة `ARCHITECTURAL_AUTHORITY`.
- الإنتاج `BLOCKED` افتراضيًا.
- الأردن `BLOCKED_PENDING_OFFICIAL_INPUT`.
- الذكاء لا يملك أي Action حساس.
- لا يوجد قرار عالمي يثبت 400 أو 500 ظهور.
- لا يوجد قرار يسمح ببيع صور إضافية أو مساحة إعلان أكبر.
- لا يوجد تعارض قديم غير مصنف.

### 9.3 اختبارات سلبية

Fixtures منفصلة تثبت أن البوابة تفشل عند:

- حذف Decision.
- تغيير Hash.
- إضافة Transition بحالة مجهولة.
- تفعيل دولة بلا Gate Evidence.
- إدخال Chat أو Delivery أو Commission كوظيفة مفعلة.
- منح AI صلاحية مالية أو أمنية.

## 10. الأمن والخصوصية

- لا تحفظ أسرار أو بيانات اعتماد داخل الحزمة.
- لا يقرأ Validator `.env` أو `.env.local`.
- لا تطبع الأداة محتوى حساسًا؛ تطبع Path وCode فقط.
- أي مدخل رسمي سري يسجل كمرجع Vault لا كقيمة.
- لا Migration إنتاجية ضمن مرحلة Authority Ingestion.

## 11. خطة البرنامج بعد تثبيت السلطة

تنفذ V13.1 في خطط مستقلة، كل واحدة تنتج برمجيات قابلة للاختبار:

1. Authority and Conflict Freeze.
2. Global Account and Country Context Contracts.
3. Authorization Envelopes and RLS.
4. Listing, Image and Contact-Reveal Contracts.
5. Exposure Capacity, Wallet and Double-Entry Ledger.
6. Search and Seven-Sector Genome.
7. UX System, Screen Registry and Accessibility.
8. Security, Survival Modes, SLOs and Recovery Evidence.
9. Jordan Activation Capsule and Controlled Pilot Gates.

لا يبدأ بند لاحق حساس قبل نجاح البوابات التي يعتمد عليها.

## 12. غير مشمول في المرحلة الأولى

- تشغيل دفع حقيقي.
- فتح الأردن أو أي دولة.
- نشر Migration إنتاجية.
- تغيير Clerk أو Supabase Runtime.
- إعادة تصميم الواجهة.
- حذف Feed أو Chat من الكود قبل إصدار Conflict Mapping واختبارات الهجرة.
- اعتماد 400 ظهور أو سعر أو ضريبة أو مزود دفع.
- إدخال قيم أسرار أو بيانات قانونية غير مقدمة رسميًا.

## 13. معايير القبول

تعتبر مرحلة Authority Ingestion ناجحة فقط عندما:

- توجد العقود وSchemas وManifest المذكورة.
- ينجح Validator على الحزمة الأصلية.
- تفشل جميع Fixtures السلبية بالرمز المتوقع.
- تدمج البوابة داخل Quality Gate دون خفض أي بوابة قائمة.
- لا تتغير ملفات Runtime أو Migrations.
- لا تظهر أسرار في Diff أو Logs.
- ينجح GitHub Actions.
- يوجد PR مستقل ومراجعة وأثر Commit.
- تبقى حالة الإنتاج `BLOCKED` وحالة الأردن غير مفعلة.
