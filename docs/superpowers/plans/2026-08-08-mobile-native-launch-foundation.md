# VVIP TIGER Mobile Native Launch Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build reproducible, auditable Android and iOS native shells from the exact verified VVIP TIGER public web artifact, with fail-closed configuration and CI evidence suitable for later Play Console/App Store signing and submission.

**Architecture:** Keep the existing web release builder as the only application-content source of truth. A new `mobile/` workspace consumes `dist/public`, verifies its `release-manifest.json` source SHA, copies only that verified artifact into `mobile/www`, then creates/synchronizes Capacitor native shells deterministically. Android and iOS projects are generated in CI from pinned dependencies rather than becoming independent application codebases; platform-specific patches are applied by checked-in scripts and verified by contracts.

**Tech Stack:** Node.js 22, Capacitor 8.4.2, Python 3.12 existing release builder, Android SDK/API 36, Java 21, Gradle generated by Capacitor, Xcode 26+, iOS 26 SDK, GitHub Actions.

## Global Constraints

- Parent security SHA: `b38521fe2e7384b69f23fb6c45c386a98ee7c8f4`.
- The mobile workspace must consume `dist/public`; it must never copy the repository root into a WebView.
- `release-manifest.json.releaseEligible` must be `true` and `sourceSha` must equal the build SHA before native synchronization.
- No `service_role`, Supabase secret key, Clerk secret key, signing password, signing private key, Apple certificate, or provisioning profile may be committed or copied into `mobile/www`.
- Capacitor dependencies are pinned to exact `8.4.2` versions for the initial foundation.
- Android `targetSdkVersion` must be `36` or higher.
- iOS CI must use Xcode `26` or later and an iOS `26` SDK or later.
- Application identifier is `com.vviptiger.app` for the launch foundation.
- Application display name is `VVIP TIGER`.
- Android/iOS store signing and actual submission remain protected owner gates; CI must fail closed when release credentials are absent rather than substituting development credentials.
- Arabic RTL and English LTR remain supported by the shared web artifact.
- Production DB and Production Edge Functions are not mutated by this plan.
