# TIGER SYNAPSE v2 + TIGER VERITY FABRIC Program Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this program one bounded slice at a time. Do not dispatch subagents unless the OWNER explicitly authorizes multi-agent execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the OWNER-approved TIGER SYNAPSE v2 product and TIGER VERITY FABRIC proof plane through small exact-head slices, beginning by restoring PR #271 to GREEN and then making the OWNER authority graph the first new foundation.

**Architecture:** The program has two coupled lanes. The SYNAPSE lane adds temporal intent, deterministic matching, Living Surface integration, Proof-of-Now, mutual disclosure, Connection Cells, hybrid intelligence, qualified advertising, and global hardening. The VERITY lane turns the stable OWNER entrypoint, existing TSRF evidence plane, exact-file web release, media-finalizer image, migrations, P01–P20 policy, live runtime witnesses, and safe rollback into one digest-bound proof graph without creating a second authority.

**Tech Stack:** Static HTML/CSS/vanilla JavaScript, selectively typed TypeScript at trusted server boundaries, Supabase/PostgreSQL migrations and RLS, Supabase Edge Functions, Node.js 22 test tooling, Node.js 24/Sharp AWS Lambda container, Python release tooling, GitHub Actions, existing TSRF evidence modules, CycloneDX, SLSA/in-toto-compatible attestations.

## Global Constraints

- The latest explicit OWNER decision marked `CURRENT_ONLY` is final for its domain.
- Every conflicting predecessor becomes `RETIRED_FROM_CURRENT_PLATFORM / HISTORICAL_ONLY` and is disconnected from runtime, current navigation, public artifacts, active tests, active configuration, current plans, and generated current documentation.
- Historical bytes may remain only as non-runtime audit, security, provenance, or decision evidence; they acquire no current authority.
- `docs/owner-control/TIGER_OWNER_CURRENT_REFERENCE_AR.md` remains the one stable OWNER entrypoint and routes to mutable truth instead of duplicating it.
- `docs/MASTER_PROJECT_STATE.md` remains the one mutable human execution state.
- Repository bytes plus exact commit/tree identity and evidence from that same source state outrank prose.
- No SYNAPSE or VERITY capability is `IMPLEMENTED` or `VERIFIED` merely because this plan is approved.
- S0 is mandatory. No new SYNAPSE or VERITY feature may hide the existing PR #271 RED state.
- No direct write to `main`, no Production mutation, and no reuse of a retired Preview link.
- Federated identity remains issuer+subject based; no first-party password authority is introduced.
- Authorization, RLS, F05 media limits, moderation, ledger integrity, platform-role, exact-file release, and fail-closed evidence boundaries remain intact.
- Silent signals may affect only local ephemeral presentation. `LIVE_NETWORK` requires explicit user activation.
- Eligibility and policy filtering occur before ranking. Sponsorship never converts an ineligible candidate into an eligible one.
- AI is optional and replaceable; deterministic access, correction, and fallback remain available.
- Offline UI never fabricates publication, verification, disclosure, message delivery, or paid-placement success.
- Web Artifact, Media Finalizer OCI Image, and Migration Bundle remain separate sealed subjects.
- Hermetic claims apply to build inputs and deterministic checks, never to live AWS, DNS, TLS, identity, or third-party state.
- Rollback promotes only a previously built verified artifact and must pass current signature, vulnerability, configuration, schema-compatibility, and health checks.
- Every slice uses RED → GREEN → focused regression → full Quality Gate → exact-head evidence → state update.
