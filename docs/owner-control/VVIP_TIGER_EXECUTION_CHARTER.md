# VVIP TIGER — ميثاق التنفيذ الجراحي

## القاعدة

> نكون جراحين، لا حدادين.

## الممنوعات

- لا تعديل مباشر على main.
- لا كود دون نطاق معتمد.
- لا إصلاح دون سبب مثبت.
- لا إعادة بناء عشوائية.
- لا حذف دون مراجعة.
- لا أسرار في الواجهة.
- لا SQL أو Production دون موافقة.
- لا نجاح وهمي للمستخدم.
- لا زر ميت.
- لا شاشة فارغة.
- لا فشل صامت.
- لا علامة ✅ قبل التحقق بعد الدمج.

1. جمع الاعتمادات.

3. تحديد السبب.

8. تقييم الحماية.
9. تقييم السرعة.
10. تصميم البدائل.
11. تصميم خطة الرجوع.
12. التحقق من main النظيف.
13. إنشاء فرع مستقل.
14. نسخة أمان عند الحاجة.
15. تنفيذ أصغر تغيير صحيح.
16. فحص Syntax.
17. فحص Whitespace.
18. فحص Security.
19. فحص Performance.
20. فحص Loading وEmpty وError وRetry.
21. فحص الهاتف.
22. مراجعة Git Diff.
23. Commit واضح.
24. Push.
25. Pull Request.
26. مراجعة صريحة.
27. دمج.
28. Post-Merge Verification.
29. تحديث المتتبع.
30. وضع ✅ عند تحقق جميع الأدلة.

## بوابة الحماية

- الهوية.
- الصلاحية.
- الملكية.
- RLS.
- Storage.
- RPC عند الحاجة.
- عدم كشف الأسرار.
- عدم تسجيل Token.
- Fail Closed.
- أقل صلاحية.
- عدم الاعتماد على الواجهة.
- حماية الإدخال والرفع.

## بوابة السرعة

- App Shell.
- Skeleton.
- تحميل تدريجي.
- Lazy Images.
- Pagination.
- Debounce.
- منع التكرار.
- Request Budget.
- Cache آمن.
- اتصال ضعيف.
- لا تعطل كامل بسبب جزء ثانوي.

## بوابة البدائل

لكل ميزة:

- Primary Path.
- Safe Fallback.
- Retry Policy.
- User Message.
- Logging Policy.
- Tiger Care Escalation.
- Rollback أو Cancel.

## حالات الأوامر

- idle
- pending
- success
- failed
- retrying
- cancelled

## إعادة المحاولة

تسمح فقط عندما:

- لا تنشئ سجلًا مكررًا.
- العملية Idempotent أو محمية.
- لا تعيد الدفع.
- لا تعيد الحذف.
- يوجد حد للمحاولات.
- يوجد تأخير متدرج.
- يستطيع المستخدم الإلغاء عند الإمكان.

## رسائل الأخطاء

المستخدم يرى:

- رسالة عربية مفهومة.
- ماذا حدث باختصار.
- ماذا يفعل الآن.
- Retry أو بديلًا.

لا يرى:

- Stack Trace.
- SQL.
- JWT.
- Token.
- Secret.
- تفاصيل الخادم.

## معيار الإنجاز

الهدف صفر عيوب معروفة عند الدمج، مع دفاعات واختبارات وبدائل تقلل أثر الأعطال المستقبلية.

لا يجوز الادعاء باستحالة حدوث أي خطأ برمجي مستقبلًا بنسبة مطلقة.
