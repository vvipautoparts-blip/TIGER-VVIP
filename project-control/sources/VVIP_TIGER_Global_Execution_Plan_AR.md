# اعتماد الوثيقة وطريقة استخدامها

هذه الوثيقة هي المرجع التنفيذي المقترح لتحويل منصة VVIP TIGER إلى منتج عالمي قابل للتشغيل التجاري. لا تعتبر أي شاشة أو مهمة مكتملة لمجرد ظهورها بصريًا؛ يكتمل العمل فقط بعد نجاح الاختبارات، التحقق الأمني، العمل على بيئة Staging، تحديث الوثائق، وتوفير خطة تراجع.

- يجب ربط كل Pull Request برقم مهمة من هذه الوثيقة.

- أي تغيير في النطاق يحتاج سجل قرار وتقدير أثر على الوقت والتكلفة.

- الأولوية للأمان والبيانات والمسار الكامل للمستخدم، لا لزيادة عدد الشاشات.

- الإطلاق العالمي يتم عبر نواة عالمية واحدة وCapability Matrix، ثم فتح الدول تدريجيًا.

# الملخص التنفيذي

يمكن تجهيز المنصة من البداية المعمارية الصحيحة لتكون عالمية، مع الاستفادة من الواجهات والوثائق والأجزاء الحالية بدل إعادة البناء الكامل. المسار الأسرع المسؤول يعتمد على فريق من 7 إلى 9 أشخاص، خدمات مدارة، PWA أولًا، محرك قطاعات واحد، وعدم الاحتفاظ بأموال صفقات المستخدمين في الإصدار الأول.

| المؤشر | التقدير |
| --- | --- |
| الجاهزية الحالية ضمن نطاق عالمي كامل | نحو 25% إلى 30% |
| المدة بفريق 7-9 متخصصين | 8 إلى 10 أشهر للإطلاق العالمي الأول |
| المدة بفريق 5-7 متخصصين | 10 إلى 14 شهرًا |
| المدة بمطور أو مطورين | 18 إلى 24 شهرًا أو أكثر |
| مفهوم 100% | اكتمال Global V1 وتشغيله التجاري، وليس توقف التطوير مستقبلًا |

# مبادئ لا تقبل التنازل

- نظام هوية واحد فقط.

- كل صلاحية حساسة تتحقق على الخادم وقاعدة البيانات.

- RLS وسياسات التخزين شرط قبل بيانات حقيقية.

- لا دفع أو نشر إنتاجي دون Audit وRollback.

- لا إطلاق عالمي دفعة واحدة دون موجات ومؤشرات منع.

- لا Microservices معقدة قبل وجود حاجة مثبتة.

- لا تطبيقين Native منفصلين قبل استقرار PWA.

- لا Escrow أو حفظ أموال صفقات المستخدمين ضمن Global V1.

## G00-01 — وثيقة تعريف المنتج العالمي

| الهدف | يحوّل رؤية المنصة إلى عقد منتج ثابت يحدد المستخدمين والقطاعات والميزات وحدود المسؤولية. |
| --- | --- |
| الفائدة للمستخدم | يعرف المستخدم بوضوح ما تقدمه المنصة وما لا تقدمه. |
| الفائدة للمنصة | يمنع تضخم النطاق ويجعل التكلفة والموعد قابلين للقياس. |
| عمل المبرمج والفريق | يجمع المبرمج وصاحب المنتج القرارات في وثيقة versioned، وينشئ قائمة In Scope/Out of Scope ويربط كل Epic بها. |
| معيار القبول الرئيسي | موافقة المالك والقائد التقني والقانوني على نسخة واحدة مرقمة. |

### التنفيذ التفصيلي

- تحليل المتطلبات السابقة وربط المهمة بالمرحلة والقرارات المعتمدة.

- تحديد نموذج البيانات وواجهات API وحالات النجاح والفشل قبل كتابة الكود.

- تنفيذ التحقق على الخادم وعدم الاعتماد على إخفاء عناصر الواجهة فقط.

- إضافة تسجيل منظم للأحداث المهمة دون تخزين أسرار أو بيانات حساسة في السجلات.

- إضافة اختبارات Unit وIntegration واختبار صلاحيات أو فشل مناسب للمهمة.

- تجربة المهمة على Staging ببيانات غير إنتاجية وتوثيق الدليل.

- تحديث الوثائق، سجل التغيير، وخطة التراجع قبل الدمج.

### مسؤوليات الاختبار والجودة

- اختبار المسار السعيد من البداية للنهاية.

- اختبار المدخلات الخاطئة والحالات الحدية والانقطاع وإعادة المحاولة.

- اختبار حسابين مختلفين عند وجود بيانات خاصة.

- اختبار الهاتف والكمبيوتر واللغة العربية والإنجليزية عند تأثير المهمة على الواجهة.

- اختبار Regression لضمان عدم كسر الوظائف السابقة.

تعد المهمة مكتملة فقط عند: مراجعة الكود، نجاح CI، نجاح الاختبارات، عدم وجود ثغرة حرجة، نجاح Staging، تحديث الوثائق، وجود Rollback، واعتماد المسؤول المحدد.

# الخاتمة التنفيذية

الطريق الأسرع والأكثر واقعية لا يتمثل في كتابة جميع الصفحات بسرعة، بل في بناء نواة عالمية موحدة وآمنة، ثم ربط كل رحلة من البداية للنهاية واختبارها تحت حمل حقيقي. عند اكتمال المراحل G00 إلى G22 وفق بوابات القبول، تكون منصة VVIP TIGER قد وصلت إلى 100% من نطاق Global V1 وقادرة على الإطلاق التجاري العالمي الحقيقي والتوسع المنضبط بعد الإطلاق.
